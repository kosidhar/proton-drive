# Share Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share an item of the drive from Files (Copy Link, Share…) and from a Share window in the app: public link with password and expiry, invite people as viewer or editor, see and remove who has access.

**Architecture:** The daemon owns every SDK call, behind a `ShareService` with control-socket routes `/share/*`. The Files extension calls those routes for Copy Link, and launches the app for Share…. The app's Share window calls the same routes through its worker, and a later start reaches a running app with a new single-instance message `share <path>`.

**Tech Stack:** Bun/TypeScript daemon (`src/`), Python Nautilus extension (`linux/nautilus/`), Rust/egui app (`native-gui/`), Proton Drive SDK `@protontech/drive-sdk` (`shareNode`, `getSharingInfo`, `unshareNode`).

**Spec:** `docs/superpowers/specs/2026-11-04-share-design.md` (issue #216)

## Global Constraints

- **Explicit actions only:** nothing is shared or unshared without an explicit click on an action that says so.
- **Copy Link** creates a link only when none exists, and never changes an existing link's password, expiry or role.
- **Confirmations:** removing the link or a person always asks first, in the app.
- **Passwords:**
  - never in `GET /share/info`;
  - only from `GET /share/password`, and only when "Show" is clicked;
  - never in the daemon's log or the activity history.
- **Invitees' addresses** never appear in log lines or activity details.
- **Off the main thread:** every network call in the extension runs off the main thread with a timeout. The app's calls run in its worker.
- **Not uploaded yet:** an item with no node in the remote index is refused with "Not uploaded yet: Proton Drive can share it once it has uploaded". So is an item that is hidden or being hidden.
- **Control socket only:** the share routes live only on the control socket (`controlServer.ts`). The TCP API (`daemonServer.ts`'s `Bun.serve` on 127.0.0.1) gets no `/share` route.
- **Paths:** routes take `path` as the item's path inside My files: relative, no leading slash, `''` refused, the same as `/availability`. Clients convert from absolute paths.
- **Errors:** route errors are 400 `{ error }` in plain words, and the app and the extension show the `error` text as it is.
- **Screenshot mode sends nothing,** as everywhere else in the app.
- **Repo rules (CLAUDE.md):**
  - test first;
  - no AI attribution in git;
  - commits are conventional, with `Refs #216`, and the last commit of the last PR has `Fixes #216`.

## Review Focus

1. **An item that exists only on this computer**, such as a new file not yet uploaded: Copy Link and Share say "Not uploaded yet…", and nothing is created. Test: `refuses an item that isn't uploaded yet, or is hidden` (Task 1).
2. **Offline, or the SDK throws:** the user sees one plain sentence, and nothing half-done is left. Tests: `an SDK failure is one plain error and nothing else happens` (Task 1) and `copy_link_reports_a_failure_and_copies_nothing` (Task 3).
3. **An item that already has a password-protected or expiring link:** Copy Link returns its URL and `shareNode` is never called. Test: `ensureLink returns an existing link unchanged` (Task 1).
4. **Passwords and addresses leaking** into info, logs or activity. Tests: `info never carries the password` and `activity says what was shared without passwords or addresses` (Task 1).
5. **Paths with spaces, unicode or a leading dash** in `--share <path>` and the single-instance message. Test: `a_share_request_carries_a_path_with_spaces_and_unicode` (Task 4).

```ts
export type ShareRole = 'viewer' | 'editor';
export interface ShareInfo {
    link: { url: string; hasPassword: boolean; expiresAt: number | null; role: ShareRole } | null;
    people: Array<{ email: string; role: ShareRole; state: 'member' | 'invited' | 'invited-not-proton' }>;
}
export class ShareError extends Error {}            // message is shown to the user as is
export interface ShareService {
    info(path: string): Promise<ShareInfo>;
    password(path: string): Promise<string | null>;
    ensureLink(path: string): Promise<{ url: string; created: boolean }>;
    setLinkSettings(path: string, change: { password?: string | null; expiresAt?: number | null }): Promise<ShareInfo>;
    removeLink(path: string): Promise<ShareInfo>;
    invite(path: string, emails: string[], role: ShareRole): Promise<ShareInfo>;
    setRole(path: string, email: string, role: ShareRole): Promise<ShareInfo>;
    removePerson(path: string, email: string): Promise<ShareInfo>;
}
export function createShareService(deps: {
    sdk: Pick<ProtonDriveClient, 'getSharingInfo' | 'shareNode' | 'unshareNode'>;
    nodeFor(path: string): { uid: string; name: string } | { refused: string };
    logActivity(entry: { action: 'share'; localRelPath: string; details: string }): void;
    now(): number;
}): ShareService;
```
- `nodeFor` is wired in Task 2 from `engine.remoteIndex.getByPath(path)` and `engine.availability.hiddenBy(path)`.

**Interfaces:**
- Consumes: Task 1's `ShareService`, `ShareError`.
- Produces: `export async function shareRoute(req: Request, url: URL, share: ShareService | undefined): Promise<Response>`. Routes and bodies:
  - `GET /share/info?path=` → `ShareInfo`
  - `GET /share/password?path=` → `{ password: string | null }`
  - `POST /share/link {path}` → `{ url, created }`
  - `POST /share/link/settings {path, password?, expiresAt?}` → `ShareInfo`
  - `DELETE /share/link {path}` → `ShareInfo`
  - `POST /share/invite {path, emails, role}` → `ShareInfo`
  - `POST /share/role {path, email, role}` → `ShareInfo`
  - `DELETE /share/person {path, email}` → `ShareInfo`
- Errors: a `ShareError` is 400 `{error}`; a bad body is 400 `{error}` naming the field; a wrong method is 405; no `share` wired is 404.
